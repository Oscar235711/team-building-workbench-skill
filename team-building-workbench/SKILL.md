# 团建工作台

为当前用户创建一个独立工作台。使用随附模板和初始化脚本，不重新从零实现，不复用别人的站点、数据库、账号、历史账单或管理员密钥。

## 只收集这些业务输入

先从用户消息读取已有信息，只询问缺少的必填项，一次问完：

- **团建人数**：1–1000 的整数。
- **团建总预算**：人民币元，大于0，最多两位小数，总额上限100万元。总预算不是人均预算。

**参考活动项目及费用可选**，不提供就继续创建，不追问。用户已提供的“每人50元”保留为人均价，“整场500元”保留为按次价；单位不明确的项目预算按整场参考额并在交付时说明。没有价格或地点就留空，不能推测为0、搬用其他部门价格或搜索补造报价。

不要求用户补充时间/玩法词库、工作台名称、季度、管理员令牌、地点或部署平台。名称默认“团建工作台”，活动期默认上海时区当前季度。可采用用户主动给出的部门名和其他明确偏好。

## 创建

1. 找到本 Skill 目录。确认 Node.js 24+ 可用；本地服务不依赖 npm 安装。
2. 把可选参考项目整理为下述 JSON；无参考项目时不传该参数。配置字段见 [references/inputs.md](references/inputs.md)。不要让用户为整理格式再回答问题。
3. 在用户的工作目录中选择一个**不存在的新目录**，执行：

```text
node <skill-dir>/scripts/create-workbench.mjs --people 20 --budget 6000 --out <new-directory>
```

有参考项目时加 `--references <absolute-json-file>`；用户给出名称时可加 `--name <name>`。脚本不会覆盖已存在的目录。重复执行前检查已创建的工作台，继续原实例或使用新目录，不重置旧数据。

脚本会生成可运行网站、独立初始配置和随机管理员密钥文件 `.env`，不在输出中打印密钥。仅把该文件位置告知网站所有者。不要把密钥放入公开回复、GitHub、前端代码、构建包或可公开下载目录。

## 运行、共享与验证

切到生成目录，运行 `node scripts/local-server.mjs`，读取实际监听地址并打开页面。确认 `/api/state` 的人数、预算正确，初始账号/方案/留言均为空。普通响应不包含管理员名册。不要把只看到首页当成共享已部署。

目标是能供同事共同使用的网站。根据**当前环境已有的托管能力**完成共享：

- 有 Sites 插件：按已安装 Sites 技能创建**新 Site 与独立D1数据库**，使用本模板的 Worker 构建，保留新站默认访问范围；从安全本地文件设置运行时 `ADMIN_TOKEN`，不得打印。读取 [references/deployment.md](references/deployment.md)。
- 有用户授权的服务器/容器平台：使用随附 Dockerfile 和独立持久卷，配置 HTTPS、`ADMIN_TOKEN`。仅在已有授权环境部署。
- 没有可用托管权限：先交付本地可运行实例和容器部署材料，明确“尚未发布互联网地址”。不要发明网址、假装已上线，或要求额外业务字段来掩盖缺少托管能力。

交付前验证原昵称登录、每人两套方案、修改方案不增加票数、缺价/缺地点标识，以及管理员L1/L2新增/改名/启停。可以在一次性测试数据库中验证，不能在真实部门数据上模拟删除账号。

## 保留的产品规则

- 预置L1工作日/周末；L2出游、下午茶、晚餐、大型室内、小型室内、自由活动。普通同事不新增L1；管理员创建后可新增、改名、启停L1/L2。改名不改历史快照或时间语义。改变已有玩法性质时新建玩法，停用旧词；不重写别人已提交的方案。
- 工号后三位＋原昵称登录；同工号其他昵称不能覆盖账号。账号以内部信任制参与，不声称员工身份已验证。只有所有者可看名册工号。
- 每人每活动期最多两套正式方案，提交后可修改；支持人数按工号去重。项目整套方案内只能使用一次，每场最多3种玩法，时间单选。
- 保留公共看板、词云、项目按玩法筛选与彩色标签、拖放、实时预算、昵称留言、历史空态、CSV、管理员账号封禁/可恢复删除。
- 金额用整数分；缺估价/地点允许提交但标记，无价不等于0。按次费用不乘人数，按人均费用才乘人数；方案分别对照总预算。
- 工作日禁止出游和大型室内项目；允许超预算方案并标识。词库具体项目提交后不能任意改写；初始待补项目可补齐一次。
- 使用真正的服务器存储SQLite或D1，不能降级成仅浏览器localStorage的“多人网站”。

最终回复给出实际访问地址或本地运行位置、人数、总预算和管理员密钥文件位置。清楚区分完成的验证与未完成的托管。
