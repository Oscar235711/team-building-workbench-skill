# 团建与部门工作台

团建是开箱即用场景；成员登记、表单收集、统计看板、留言和管理员权限结构也可作为部门内部工作台的搭建参考。其他用途按用户需求适配，不直接宣称已具备通用业务功能。

## 输入

仅补问缺少的必填项：**人数**（1–1000整数）、**总预算**（人民币元，大于0、最多两位小数，上限100万元）。参考活动及费用选填，不提供就继续。人均价与整场价分别保留；未提供的估价、地点留空，不补造数据。

预置时间、玩法词库，创建后由管理员维护；无需使用者另填名称、季度、词库、令牌或部署平台。默认名称“团建工作台”，默认上海时区当前季度。可采用用户主动提供的部门名。

## 创建

先查看当前宿主的应用创建与发布工具。支持终端时，使用Node.js 24+：

```text
node <skill-dir>/scripts/create-workbench.mjs --people 20 --budget 6000 --out <new-directory>
```

输出目录必须是用户工作目录下不存在的新目录。可选 `--references <JSON文件>`、`--name <名称>`，格式见 [inputs.md](references/inputs.md)。脚本只读取随附模板和指定参考文件，写入新目录；不联网、不执行外部命令、不改原工作台。

脚本为每个实例生成独立配置和随机管理员凭据，保存在该实例的 `.env`。仅告知所有者文件位置；凭据、数据库和真实登记数据不进入前端、公开仓库或上传包。

只有原生应用编辑器时，参考 `assets/workbench/` 按宿主格式接入，保留服务端权限与共享存储。

## 运行与发布

在生成目录运行 `node scripts/local-server.mjs`，默认只监听本机。优先使用当前宿主已有的网页发布能力；Claude、Codex、千问办公、WorkBuddy、DeepSeek的表达示例见 [native-publishing.md](references/native-publishing.md)。其他部署方式见 [deployment.md](references/deployment.md)。

遵守宿主权限和用户选择的访问范围。公开发布使用应用文件和安全配置接口，排除凭据、数据库、备份及日志。每个部门使用独立存储；需要多人共享的数据保存到服务端，不以聊天分享、源码预览或各自浏览器存储替代。

检查配置、页面与核心操作，按实际结果交付。遇到影响使用的问题直接说明，不编造发布地址或执行结果。最终回复以**访问链接、人数、预算和管理员使用方式**为主，技术记录放到项目文件中。

## 产品规则

- L1预置工作日/周末，L2预置出游、下午茶、晚餐、大型室内、小型室内、自由活动。管理员可新增、改名、启停；普通用户不新增L1或改写既有分类。
- 工号后三位与原昵称登录，同工号其他昵称不能覆盖账号；该入口是内部信任制。只有管理员可查看登记名册工号。
- 每人每期两套方案，提交后可修改，统计取当前版本。每场时间单选、玩法最多3个，每个项目在整套方案中只选一次。
- 保留预算测算、项目筛选与拖放、词云、昵称留言、CSV及账号封禁/可恢复删除。缺估价、缺地点分别标记；按次费用不乘人数。
- 工作日不安排出游和大型室内；超预算方案可提交并标记。具体项目提交后固定，初始待补候选可补齐一次。
- 金额用整数分；首份提交后锁定该期人数、预算。修改显示名称不重写既有方案快照或分类语义。
